## Linux source and command boundary

[linux/AGENTS.md](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/AGENTS.md) maps the client. [executor.py](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/src/musegadget/executor.py) declares `COMMAND_SPECS` and dispatches in `Executor.run`; [fileops.py](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/src/musegadget/fileops.py) implements file transfer, while [link_client.py](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/src/musegadget/link_client.py) handles session/control messages. These are the files to inspect before an SDK extension. A custom command needs a spec, dispatcher branch, child process with `self._child_options()` for machine access, and an executor test.

For `system.run`, required `command` and optional `cwd`/`timeout_ms` are actual parameters. It runs `/bin/bash -c` as the selected run-as account with that account's permissions, including sudo access if that account has it. The declared timeout default is 120000 ms and maximum 600000 ms; stdout and stderr each cap at 96 KiB. Use a bounded read-only client call first, then only the requested write. Load credentials from approved storage without printing them or embedding them in logged command text. `file.read`/`file.write` transfer at most 64 KiB per chunk; do not send binary scans/media as terminal output. Prepare documents where the device skill requires, then transfer only approved final bytes if the local client needs them.

## Device-specific handoff and acceptance evidence

- **Handoff:** Record exact model/firmware, device ID reference, Tuya protocol version, schema source and intended mission transition. Load local key from approved storage; do not print it. Read the pinned Tuya dependency before adapting a client transport.
- **Acceptance:** Capture fresh decoded battery/error/mission state before and after. Record docking requested versus actually docked. TCP or packet acknowledgment is insufficient; reconcile uncertain delivery before another movement write and preserve model-specific datapoint meanings.
- **Runtime evidence:** `musegadget info` reports identity/pairing; `sudo journalctl -u musegadget -f` shows runtime failures. Healthy startup includes `commands run as <user>`, `Noise session established`, `sent link.register` and `registered with the Muse`. These prove SDK registration, not this device's action. Report the device evidence above separately.

If you actually modify the Linux SDK, run `uv run --with pytest --with . pytest` from `linux/`; [tests/test_executor.py](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/tests/test_executor.py) covers command behavior and [tests/test_link_client.py](https://raw.githubusercontent.com/facebookincubator/muse-gadget-sdk/468e5ba629f988ad107ba472555a8b632faac0d3/linux/tests/test_link_client.py) uses an in-process fake VM with a real Noise handshake. Pairing/Noise changes additionally need the documented Python 3.9/cryptography 3.3.2 check; installer changes need ShellCheck. A deployment restarts the service and can kill an active command: inspect recent invoke logs first, then require registered-with-Muse and no traceback after deployment. Unit tests require no hardware, but do not establish real Tuya eufy RoboVac Cleaning and Docking compatibility.
